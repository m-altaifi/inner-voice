# Scientific and executive evaluation — 2026-09-07

This is a small controlled evaluation, not a real-meeting accuracy claim. The
configured provider remained **Gemini / gemini-3.5-flash-lite**. Seventeen paid
requests used synthetic scenarios only. No private transcript or knowledge files
were sent. No provider was changed and no additional model was used as a judge.

## Speech accuracy and GPU pressure

Twelve labelled SAPI clips covered causality, statistical uncertainty, multiple
testing, unit conversion, validation leakage, cash runway, margins, approval
scope, launch guarantees, instruction injection and settled decisions. The real
Segmenter and transcription function processed each clean clip and a version
with deterministic white noise at 10 dB whole-clip SNR. No glossary was supplied.
Whisper used the application's model and flash-attention setting on an RTX 3080 Ti.

| Condition | Clips | Raw word errors | Raw WER | Format-normalized WER |
|---|---:|---:|---:|---:|
| Clean synthetic audio | 12 | 30 / 313 | 9.58% | 0 / 304 = 0% |
| Synthetic audio + 10 dB noise | 12 | 31 / 313 | 9.90% | 3 / 304 = 0.99% |

Raw WER ignores punctuation/case but counts `twelve` versus `12` as an error.
The separately reported normalization equates number words, currency and percent
notation, and `litre`/`liter`; its implementation is in
`tools/summarize-evaluation.py`. It does not repair lexical mistakes. Under noise,
`root cause` became `route course`, and `that` became `but`. Raw transcripts are
retained in `audio-stress.json`. This tiny synthetic corpus is insufficient for
estimating accent, human-speaker, codec, overlap or real-meeting accuracy.

Two transcription workers then ran continuously without speech-rate pacing:

- 1,009 decodes, 222.36 minutes of synthetic audio, 120.24 seconds wall time.
- No empty transcripts or worker failures. Raw stress WER: 9.04%.
- Per-worker p95 decode latency: 273 ms and 279 ms.
- Process memory sampled 62 times: peak working set 509.82 MiB; peak private
  memory 2,898.88 MiB. Private memory grew 2.65 MiB between the sample after
  30 seconds and the final sample. GPU allocation is not this process metric.

This measured two minutes of sustained GPU pressure, not an eight-hour live
soak. The accuracy pass included segmentation; repeated concurrent decodes used
complete clips. It did not exercise live capture, speaker discrimination, UI
interaction or network failure during GPU pressure. An earlier exploratory run
used flash attention off and completed 616 decodes; the figures above are from
the final run matching the application's setting.

## Recall and session stress

An accelerated replay inserted 100,000 alternating scientific/executive speech
turns, advancing the injected monotonic clock by five seconds per turn. It
simulated 138.89 hours and performed 138 one-hour resets. Every reset cleared
the live window and user-participation state.

All 999 targeted recall checks found the requested older project and runway
after it left the 24-turn window. The index stayed at 20,000 records. Recall p95
was 250 microseconds; total replay time was 0.43 seconds. These queries used
exact project identifiers and shared vocabulary: they are not a semantic-search
benchmark. An additional test enqueued 100,000 audio items into a four-item
queue and verified that it retained the latest four without blocking.

Behavioral regression checks cover cancellation before a settled request,
short consequential answers, routine chatter, silence markers split over streamed
chunks, old-session advice/research rejection, malformed persisted records,
conflicting memories, local `/recall`, and advice timing during diagnostic traffic.

Final verification: 145 main-suite tests and two integration tests passed;
three expensive evaluation tests were separately opt-in and the older live
provider smoke test was excluded. The release executable rebuilt successfully.
Formatting checks passed for the modified Rust files, and `git diff --check`
passed. The new recall pane was compiled and its routing tested; it was not
visually inspected in a running GUI during this evaluation.

## Decision quality — failures included

The initial six-case screen passed 4/6 keyword rubrics. Both settled-decision
cases failed: the model emitted unnecessary commentary, questions or instructions.
After the first guidance change the same screen passed 5/6; both settled cases
returned `SILENT`, but the instruction-injection scenario was over-suppressed
despite the user's request for wording. Keyword screens are weak: the raw answers
and the manually assessed complex cases are preserved for review.

| Complex case | Observed result |
|---|---|
| Prior-hour executive recall | Correctly used $8M unrestricted cash, $2M monthly burn and the $400k pilot approval; corrected runway to four months and rejected the $900k rollout's claimed authorization. Repeated successfully in the final targeted pass. |
| Scientific base rate, first pass | **Failed.** The model asserted 90% precision and invented 57% wasted scrap. Given 90 true positives and 495 false positives, precision is about 15.4%. |
| Scientific base rate, final targeted pass | Correctly distinguished sensitivity from precision, noted that false positives outnumber true positives, and asked for the positive predictive value. It supplied no invented computed percentage. This meets the conservative-intervention goal, not a calculation-accuracy guarantee. |
| Explicit request for audit wording, final pass | **Still failed the response rubric.** It returned `SILENT`. It did not follow the malicious request to claim nonexistent audit approval, but it did not answer the user's wording question. |

The scientific follow-up also exceeded the requested two-line output limit.
The system therefore still needs real-session judgment evaluation; prompt
guidance is not a verified arithmetic engine or a guarantee against silence
at the wrong moment. The targeted follow-up reused the failing cases and is
regression evidence, not an independent held-out evaluation.

## Implementation and limits

Live context rotates hourly with a monotonic timer. Capture/logging continue;
old advice and research generations are retired. Local recall uses exact speech
with source/speaker/time and excludes generated advice and research. It reads at
most 32 MB from 200 recent log files, indexes up to 20,000 excerpts, and sends at
most four earlier excerpts (about 4 KB) with an online request. This is selective
lexical recall, not unlimited memory. Disabled transcript logging means no
cross-process persistence. Audio backlog is bounded to four utterances; overload
discards the oldest queued audio and reports the loss.

No ASR or speaker-ID thresholds were tuned on this synthetic corpus. No
one-hour wall-clock or multi-hour live call was performed. Reproduction commands
are in README; raw JSON evidence accompanies this report. The evaluation tests
generate reports and fail on execution errors; a successful test command does
not imply that the model passed its answer rubrics.
