# Memory and awareness validation — 2026-09-10

The eight dependent PRs add attributed long-term knowledge, bounded working
context, background consolidation and local inspection/correction controls.
This report records infrastructure behavior. Extracted claims remain reported
evidence; these checks do not establish factual accuracy or human-like awareness.

## Failure and lifecycle coverage

| Scenario | Verified behavior |
|---|---|
| Invalid JSON, extra fields, missing/wrong evidence IDs, repeated batch | Reject the entire extraction; no partial claims or cursor advancement |
| Oversized encoded speech | Reject before it can block every later extraction batch |
| Three extraction failures | Quarantine the failed batch; retries use normal request slots |
| Mute before request | Keep speech local until advice is armed; local HTTP mock observes zero requests before arming |
| Mute during HTTP request | Retire the response; no learned claim is published, pending evidence remains |
| Clock rollback and restart | Persisted reservations preserve five-minute spacing and twelve requests per rolling hour |
| Old logs and incomplete JSONL tail | Read registered new sessions only; wait for a final newline |
| Enable during a session | Capture the file offset synchronously; skip speech before the enable point even if the worker starts later |
| Same-length source edit, deletion, retention expiry | Remove affected derived knowledge and signal snapshot refresh |
| Malformed record, oversized source, invalid source path | Preserve original files; skip/quarantine visibly; healthy registered sources continue |
| Deleted memory and delayed extraction | IDs are not reused; an obsolete batch cannot attach to new evidence |
| Schema version 1 migration | Preserve evidence, completed/confirmed claims, audit history and budget; foreign-key checks pass |
| Corrupt or future-version database | Fail without changing its bytes; runtime failure clears cached learned context |
| Conflicting owners and anonymous speakers | Retain disputes; anonymous speaker labels do not authorize corrections across sessions |
| User confirmation, completion, dismissal and repetition | Persist changes across reopening; repetition does not reopen a completed item |
| Logging disabled | Worker HTTP tests use in-memory SQLite; no persistent source is registered |
| Cross-project retrieval | Require project scope or the matching session; shared words and project-name substrings cannot cross scopes |
| Hourly/source reset and participation | Clear transient observations; cap the window at 24 turns; old participation expires |

Scope and evidence-ID validation cannot prove that an extraction faithfully
paraphrases its source. Model judgment, commitment detection and paraphrase
accuracy still need a separate, opt-in evaluation with synthetic prompts.

## 100,000-turn accelerated replay

The final memory store ingested 100,000 synthetic attributed turns and applied
fixture extractions through its normal validation/transaction path. Ephemeral
retention kept 20,000 claims. Retrieval used the actual lexical index and prompt
renderer, with 1,000 queries distributed across the retained project scopes.

- Correct scoped answers: **1,000 / 1,000**.
- Retrieval p95: **4,561 microseconds**; maximum: **5,380 microseconds**.
- Largest returned knowledge context: **328 bytes**, below the 4 KB limit.
- Total replay and retrieval time: **7.21 seconds**.
- Provider calls: **0**.

The latency measures local knowledge retrieval, excluding audio transcription,
working-context assembly, provider inference and GUI rendering. It is one run
on this development machine, not an end-to-end latency guarantee.

Raw result: [memory-replay-100k.json](memory-replay-100k.json).

## One-hour paced run

A separate test executable built from M06 (`d8210ad`) ran for **3,602.06 seconds**
using real JSONL writes, SQLite and the monotonic context clock. It processed
**721** synthetic speech turns, crossed **one hourly context rotation**, and
closed/reopened the store halfway through. The pending commitment remained
retrievable, and no speech records were pending at completion.

There were **13 reserved extraction slots across the run**, with the thirteenth
after the first hour elapsed. Reservations enforce at most twelve per rolling
hour; the first slot had expired before the thirteenth was reserved. Extraction
responses came from fixtures, so provider calls were **zero**.

The isolated executable let final implementation work proceed while the paced
run continued. It predates the M08 migration and source-validation fixes, which
were checked by the final release regression suite. This is a paced storage and
context test, not a one-hour microphone, network or GUI soak of the final binary.

Raw result: [memory-paced-hour.json](memory-paced-hour.json).

without taking focus, borderless layout, hotkey registration/dispatch, existing

## Reproduce

Run from the repository on a Windows machine with the documented build tools:

```powershell
.\build.ps1 test --release --offline -- --skip live_provider_returns_advice
.\build.ps1 clippy --release --offline --all-targets -- -D warnings
.\build.ps1 fmt -- --check
git diff --check
.\build.ps1 build --release --offline
.\build.ps1 test --release --offline knowledge_replay_100000_turns -- --ignored --nocapture
.\build.ps1 test --release --offline paced_memory_hour_with_restart -- --ignored --nocapture
powershell -NoProfile -File .\tools\memory_ui_smoke.ps1
```

The paced test defaults to 3,602 seconds. `IV_SOAK_SECONDS` can shorten a local
debug run, but a shorter run is not evidence of crossing an hourly reset.
Synthetic evaluation output and screenshots stay under ignored runtime paths;
only the two selected aggregate JSON reports are committed here.
